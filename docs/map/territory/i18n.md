# i18n

## What it is

Putting every user-facing string in the user's language. Each package has its own dictionary and its own `t()`; both `t()`s are the same `translate` from `shared/i18n.ts`, which also defines the closed `Locale` type (`ko-KR`, `en-US`) and `TranslationOverrides`. `shared/` is not a package: tsup inlines it into each package's `dist`, code and declarations both, so each package still installs alone.

**None.**

## Design model

- Lookup order: an override from `TranslationOverrides` for that key and locale — an empty string counts, so an app can blank a label (maintainer, 2026-10-29) — then the package dictionary, then the key itself. A missing key renders as its own name.
- `t(key, locale, overrides?, params?)` replaces every `{name}` occurrence with `params[name]` literally (`split`/`join`, so `$` patterns in a value are not interpreted).
- `TranslationKey` is the union of the package dictionary's keys, so a typo in a `TranslationKey` fails to compile. The dictionary is declared with `satisfies Record<string, Record<Locale, string>>` rather than annotated: an annotation widens `keyof` to `string`. `as const` is not used either, because it would put every translated string into the published `.d.ts` as a literal type. `satisfies` is what rejects an entry with a missing or extra locale.
- `t()` reads the dictionary through `lookup`, the same object typed `Record<string, Record<Locale, string>>`, because a keyed dictionary cannot be indexed by an arbitrary string under `strict`. The assignment also rejects a missing locale, but not an extra one.
- `t()` still accepts any string: `errorMessage` builds `<prefix>.<code>` for `LoginView` and `AccountDeleteView`, `SubscriptionView` builds `app.<appId>`, and apps add keys through overrides. A typo passed straight to `t()` still compiles.
- Every component that renders text takes a `translations` prop and passes it to every `t()` call, and on to the components it renders.
- Each package re-exports `Locale` and `TranslationOverrides` from `shared/i18n.ts`, so the published names stay per package while the definition is one.
- Each package's `tsconfig.json` has no `rootDir` and includes `../../shared`; a `rootDir` of `src` rejects the shared file (TS6059).
- Adding a language touches `Locale` in `shared/i18n.ts`, both dictionaries, and the terms markdown.

## Blast radius

- [terms-content](terms-content.md) — terms are keyed by `Locale`; a new locale needs its markdown files.
- [login](login.md), [terms-agreement-ui](terms-agreement-ui.md), [account-screens](account-screens.md) — auth keys; renaming a key silently renders the key name.
- [login](login.md), [subscription-status-ui](subscription-status-ui.md) — two callers detect missing text by `t()` returning the key itself: auth's `errorMessage` (no `<prefix>.<code>` text → `<prefix>.generic`, used by `LoginView` and `AccountDeleteView`) and `SubscriptionView`'s `appLabel` (no `app.<appId>` text → the raw id). Changing that fallback breaks both. A `has()` helper was declined by the maintainer (#7) because it would have copied each package's override rule; the rules are now one `translate`, so that reason no longer holds.
- [subscription-status-ui](subscription-status-ui.md) — subscription keys, and the `{param}` substitution they rely on.
- [plan-catalogue](plan-catalogue.md) — every entitled app id needs an `app.<id>` key.

## Known holes / open

- `useCheckout`'s error messages are English strings, not `t()` keys.
